Scientific Workflows on the Eve of the Butlerian Jihad

A practical manifesto for scientific software in the era of vibecoding: what actually helps, what breaks, and how to ship reproducible research faster.

Published

February 26, 2026

Why This Post Exists

Most of us did not get into research because we love debugging environments, waiting on queues, or fighting invisible data bugs. We got into research because we want to answer hard questions.

Modern scientific work is a software project. If your codebase is brittle, your science is brittle. If your workflow is reproducible, your science scales.

This post is a practical field guide: what breaks, what helps, and what I would actually recommend to students doing serious technical work in 2026.

transpose = (obj) => {
  if (!obj || Object.keys(obj).length === 0) return [];
  const keys = Object.keys(obj);
  if (keys.length === 0 || !obj[keys[0]]) return [];
  return obj[keys[0]].map((_, i) => {
    const r = {};
    keys.forEach(k => r[k] = obj[k][i]);
    return r;
  });
}

The lesson is not “software is annoying.” The lesson is that if you do not invest in structure up front, the friction compounds.

The Iron Rule

  • If you take the time to build software the right way, you worry you will not reuse it.
  • If you skip structure, the project eventually punishes you.

Both are true. The strategy is to build just enough structure that your future self (or collaborator) can trust and extend the work.

Each layer in the pipeline maps to a tool with a clear job:

Problem Tooling Choice
Reproducible environment uv + lockfiles
Data validation Pydantic schemas

Reliability Pytest + CI
Workflow automation Snakemake

This is not the only valid stack. It is one coherent stack that minimizes glue code and hidden state.

Why Quarto Matters

Quarto is not just a rendering tool. It is the integration layer where analysis, narrative, equations, and interactivity can live in one reproducible artifact.

That matters for collaboration and for publication. It is harder to misplace a figure or lose a parameter setting when the notebook that generated it is the document.

A Live Toy Model

Interactive simulations build intuition faster than static plots and let you probe edge cases without touching code.

viewof settings = Inputs.form({
  N: Inputs.range([50, 800], {label: "Agent Count", step: 10, value: 400}),
  radius: Inputs.range([10, 150], {label: "Radius", step: 5, value: 45}),
  noise: Inputs.range([0, 1], {label: "Entropy", step: 0.05, value: 0.15}),
  speed: Inputs.range([1, 10], {label: "Velocity", step: 0.5, value: 4.5}),
  attraction: Inputs.range([0, 5], {label: "Attraction", step: 0.1, value: 2.5})
})
{
  const width = 780;
  const height = 480;
  const canvas = html`<canvas width="${width}" height="${height}" style="width: 100%; height: 480px; border-radius: 12px; background: #000;"></canvas>`;
  const ctx = canvas.getContext("2d");

  let agents = Array.from({length: settings.N}, () => ({
    x: Math.random() * width,
    y: Math.random() * height,
    theta: Math.random() * Math.PI * 2
  }));

  function update() {
    if (agents.length !== settings.N) {
      if (agents.length < settings.N) {
        for (let i = agents.length; i < settings.N; i++) {
          agents.push({x: Math.random() * width, y: Math.random() * height, theta: Math.random() * Math.PI * 2});
        }
      } else {
        agents = agents.slice(0, settings.N);
      }
    }

    agents = agents.map((a) => {
      let sumSin = 0, sumCos = 0, count = 0;
      for (const b of agents) {
        let dx = b.x - a.x, dy = b.y - a.y;
        if (dx > width/2) dx -= width;
        if (dx < -width/2) dx += width;
        if (dy > height/2) dy -= height;
        if (dy < -height/2) dy += height;
        if (dx*dx + dy*dy < settings.radius * settings.radius) {
          sumSin += Math.sin(b.theta);
          sumCos += Math.cos(b.theta);
          count++;
        }
      }
      const avgTheta = Math.atan2(sumSin / Math.max(count, 1), sumCos / Math.max(count, 1));
      const newTheta = avgTheta + (Math.random() - 0.5) * settings.noise;
      let x = a.x + Math.cos(newTheta) * settings.speed;
      let y = a.y + Math.sin(newTheta) * settings.speed;
      if (x < 0) x += width; if (x >= width) x -= width;
      if (y < 0) y += height; if (y >= height) y -= height;
      return {x, y, theta: newTheta};
    });
  }

  function draw() {
    ctx.fillStyle = "rgba(0, 5, 15, 0.45)";
    ctx.fillRect(0, 0, width, height);
    for (const a of agents) {
      const hue = 280 + Math.sin(a.theta) * 45;
      ctx.strokeStyle = `hsla(${hue}, 85%, 65%, 0.8)`;
      ctx.beginPath();
      ctx.moveTo(a.x, a.y);
      ctx.lineTo(a.x - Math.cos(a.theta) * 10, a.y - Math.sin(a.theta) * 10);
      ctx.stroke();
    }
    update();
    requestAnimationFrame(draw);
  }
  requestAnimationFrame(draw);
  return canvas;
}

What I’d Tell Students

  1. Build one reproducible pipeline end-to-end before optimizing anything.
  2. Keep your core logic in modules, not only notebooks.
  3. Let CI fail early instead of discovering mistakes during final writeup week.
  4. Use LLMs as force multipliers, not as replacements for structure.

Closing

The future is not “AI replaces scientific programming.” The future is that scientific programming becomes more ambitious because the fixed costs of good engineering drop.

That only works if we still care about validation, reproducibility, and clarity.

In other words: let the tools remove friction, but keep your scientific standards high.
