The Iron Rule of Scientific Software Development

  • If you take the time to build out code the right way you will never use it
  • If you write sloppy code it will bite you in the ass
  • Damned if you do. Damned if you don’t.

Your Workflow

The Process

  • You have data or simulation parameters.
  • You have a model (ABM/statistical/ML).
  • You want to run sweeps with fixed logic.
  • You want to collect & visualize results.
  • You want to turn plots into a publication.

The Goal

Automate the plumbing so you can focus on the science.

The Foundation

1. What Python Already Offers

  • No Logic Notebooks: Logic lives in .py source code files make your source code portable and pip installable
  • Type Hinting: Python is dynamically types but it has a type-annotation system, USE IT!
  • Git Branches and PRs: Especially when collaborating on a codebase, USE branches, branch often and use pull-requests to merge changes back into main

1. The Environment

Reproducible UV

  • Speed: Orders of magnitude faster than pip/conda.
  • Locking: uv.lock ensures your code runs everywhere.
  • Examples: pyproject.toml, uv.lock

Docs: astral.sh/uv | git-scm.comhttps://github.com/WillHWThompson/PythonForScientificDevelopment

AD and Hardware Acceleration

Not just for deep learning

  • Rule of Thumb: If it’s vectorized in Numpy, it’s ready for the GPU np. to jnp..

  • Parraell Processing Across GPUS: Jax’s vmap makes it easy to run 1,000s of simulations on a single GPU in parralell

  • Automatic Differentiation: Gradients for any simulation, ODE solver, or Agent-Based Model (ABM).

  • Examples: src/models/bert_adapter.py

Docs: jax.readthedocs.io | pytorch.org

4. Custom Data Structures and Type Validation

Validated Data

  • Pydantic: Ensure the inputs and outputs have the right structure
  • LLM Context: Type-validated data structures make it much easier for LLMs to reason about inputs and outputs
  • Examples: src/core/schema.py, src/data/loader.py

Docs: pydantic.dev

Data Plumbing

2. The Workflow

Snakemake

  • Automatic workflow generation: Specify components, Snakemake automatically builds the whole sweep.
  • Slurm Integration: Manages Slurm jobs without bespoke batch scripts.
  • Amnesia Proof: Only runs what hasn’t been run, identifies stale results.
  • Examples: Snakefile, ./workflows

Docs: snakemake.github.io | vacc.uvm.edu

3. Unit Testing

Pytest Rigor

  • Logic Checks: Validate each part of your research code.
  • Integration: Ensure the whole system plays together nicely.
  • Examples: tests/test_nlp_logic.py

GitHub Actions

  • Automation: Run tests on every push.
  • Trust: Know your “vibe” is actually correct.
  • , .github/workflows/ci.yml

Docs: pytest.org | github.com/features/actions

5. Storing Data

Databases

  • Pydantic ORM: Use SQLModel for a type-safe Python interface to DuckDB/WebDB.
  • Parquet + DuckDB: SQL speed on flat files.
  • Examples: notebooks/quarto/dashboard.qmd,

Docs: UVM WebDB|duckdb.org

Summary

  1. Accept that you are a Developer. We are all software engineers now.
  1. Standardize Environments. Use UV and lockfiles.
  1. Automate Workflows. Let Snakemake handle the graph.
  1. Verify and Aggregate. Use DuckDB for insane speed.
  1. Focus on the Science. Let automation handle the heavy lifting.
